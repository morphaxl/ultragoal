# Multi-agent orchestration research — June 2026

Four parallel research sweeps (Anthropic official, AI-engineering practitioners, Chinese labs, academic agent-systems), run 2026-06-11, hunting orchestration mechanisms — orchestrator/worker/judge topologies, parallel fan-out, role asymmetry, panel judging — that add product value to ultragoal's goal loop. Companion to the [June harness sweep](harness-research-2026-06.md).

**Headline finding, convergent across all four communities:** multi-agent structure pays on the *verification* side, not the generation side. Under compute-matched comparisons, generator-side multi-agent (debate, peer swarms, mixed-model blending) fails to beat a strong single agent — while independent, mutually-blind, aspect-split verifier ensembles deliver consistent 8–20% gains and keep scaling where repeat-sampling plateaus.

## Anthropic

- **Orchestrator-worker fan-out with explicit sizing rules** — lead agent spawns 3–5 parallel subagents, each with explicit objective, output format, and boundaries (vague delegation caused duplicated work); embed scaling rules in the orchestrator prompt: 1 agent for simple facts, 2–4 for comparisons, 10+ for complex research. Multi-agent beat single-agent Opus by 90.2% on their research eval — at ~15× token cost; token usage alone explained 80% of variance. The win is specific to decomposable, read-heavy work. [Multi-agent research system](https://www.anthropic.com/engineering/multi-agent-research-system)
- **Single-call rubric judge beat multi-judge panels** *for their research product* — one LLM judge scoring fixed dimensions outperformed panels; judge end state, not trajectory. (Counter-evidence to panels in their setting; the academic results below find the opposite for per-aspect verification — the difference is aspect-*split* vs same-rubric-replicated.) [Same post](https://www.anthropic.com/engineering/multi-agent-research-system)
- **Fresh-context verifier subagents officially beat self-critique**; prefer async orchestrator↔subagent communication; long-lived subagents resumable by agentId. [Prompting Claude Fable 5](https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/prompting-claude-fable-5) · [Agent SDK subagents](https://code.claude.com/docs/en/agent-sdk/subagents)
- **Agent teams**: file-locked shared task list, plan-approval gating, and three exit-2 quality hooks — `TeammateIdle`, `TaskCreated`, `TaskCompleted`; adversarial competing-hypotheses debugging ("spawn ~5 teammates to disprove each other"); sizing heuristic: "three focused teammates often outperform five scattered ones." Experimental, env-flag-gated. [Agent teams](https://code.claude.com/docs/en/agent-teams)
- **Advisor tool** (beta): executor consults a stronger model mid-task; Sonnet + Opus advisor = +2.7pp SWE-bench at −11.9% cost. API-only, but the call-timing patterns (consult before first write, before declaring done) port to prompts. [Advisor tool](https://platform.claude.com/docs/en/agents-and-tools/tool-use/advisor-tool)
- **Dynamic workflows**: model-authored orchestration scripts run outside the context window; 16 concurrent agents; bundled deep-research votes per claim and filters those failing cross-checks. v2.1.154+. [Workflows](https://code.claude.com/docs/en/workflows) · [Announcement](https://claude.com/blog/introducing-dynamic-workflows-in-claude-code)
- **Role asymmetry via initial prompt only**; state crosses context boundaries through artifacts (feature-list JSON, progress file, git history), not conversation. [Effective harnesses](https://www.anthropic.com/engineering/effective-harnesses-for-long-running-agents)

## Practitioners

- **Cognition**: "Don't Build Multi-Agents" (actions carry implicit decisions; conflicting decisions produce bad results) → by Mar 2026, coordinator-Devins ship only with each worker *independently verifying its own changes before reporting back*. [Don't build multi-agents](https://cognition.ai/blog/dont-build-multi-agents) · [Devin manages Devins](https://cognition.ai/blog/devin-can-now-manage-devins)
- **Cursor**: flat peer coordination collapsed (20 equal agents ≈ throughput of 2–3); the working topology is asymmetric planner/worker/judge where workers never talk to each other and a judge gates each cycle. "Prompting over architecture." [Scaling agents](https://cursor.com/blog/scaling-agents)
- **StrongDM software factory**: no-human-review pipeline gated by *holdout scenarios* kept outside the developing agent's context; observed agents writing `return true` and rewriting tests when checks were visible. [Software factory](https://www.strongdm.com/blog/the-strongdm-software-factory-building-software-with-ai) · [Willison digest](https://simonwillison.net/2026/Feb/7/software-factory/)
- **LLM juries in practice**: 3 small judges with uncorrelated error profiles, majority vote, fail-closed on ties; >95% inter-judge agreement means "you bought one verdict three times" — diversity is the point. [orq.ai juries](https://orq.ai/blog/llm-juries-in-practice)
- **Amp's oracle**: a stronger reasoning model as read-only second-opinion judge — advises, never edits. [Amp manual](https://ampcode.com/manual)
- **Ralph lineage**: monolithic single agent, verification as backpressure; "non-deterministic agents coordinating = microservices, a red hot mess." [Huntley: loop](https://ghuntley.com/loop/) · corroborated at scale by [OpenAI harness engineering](https://openai.com/index/harness-engineering/) (~1M LOC, 3 engineers, one harness, no fleet)
- **Gas Town** (Yegge): durable work state in git-stored items, disposable sessions; each watcher simpler than what it watches, terminating in a deterministic daemon. [Inside Gas Town](https://www.augusteo.com/blog/inside-gas-town)
- **Fresh-context-per-iteration + asymmetric validate** (cheaper model writes, smarter model validates). [HumanLayer RPI](https://linearb.io/blog/dex-horthy-humanlayer-rpi-methodology-ralph-loop)
- Parallel agents pay only for well-specified, independently verifiable tasks; the binding constraint is review capacity. [Willison: parallel agents](https://simonwillison.net/tags/parallel-agents/) · [Lance Martin: agent design patterns](https://rlancemartin.github.io/2026/01/09/agent_design/)

## Chinese labs

- **Tongyi IterResearch / Heavy Mode** (Alibaba): per-round workspace reconstruction around an evolving report; parallel explorers feed a separate synthesis model. [arXiv:2510.24701](https://arxiv.org/abs/2510.24701)
- **Kimi K2 self-critique calibration** (Moonshot): the critic is recalibrated on *verifiable-reward* tasks before judging subjective ones — objective accuracy gates subjective trust. [arXiv:2507.20534](https://arxiv.org/abs/2507.20534); K2.6's adaptive coordinator sizes its own swarm per task (BrowseComp 86.3 swarm vs 78.4 single). [Kimi K2 repo](https://github.com/MoonshotAI/Kimi-K2)
- **AWorld Guard Agent** (Ant Group): paired execution + guard agent intervening at critical mid-trajectory moments beats end-only checking on noisy tool-heavy tasks. [arXiv:2508.09889](https://arxiv.org/abs/2508.09889)
- **Step-DeepResearch checklist judger** (StepFun): atomic Extract → Plan → Verify → Replan agents; 61.4% on Scale AI Research Rubrics with a 32B model. [arXiv:2512.20491](https://arxiv.org/abs/2512.20491)
- **OWL/Workforce** (CAMEL-AI): optimize only the planner, keep workers frozen/pluggable — planner-side prompts are the highest-leverage surface. [arXiv:2505.23885](https://arxiv.org/abs/2505.23885)
- **MacNet collaborative scaling law** (Tsinghua): agent-ensemble gains follow logistic growth with *early saturation* — 2–3 diverse judges capture most of the gain. [arXiv:2406.07155](https://arxiv.org/abs/2406.07155)
- **Youtu-Agent** (Tencent): meta-agent interviews the user and auto-generates the agent config — same shape as ultragoal's interview → rubric co-authoring. [youtu-agent](https://github.com/TencentCloudADP/youtu-agent)

## Academia

- **MAST failure taxonomy** — 14 failure modes from 1,600+ annotated traces: specification issues ~42–44% of failures, inter-agent misalignment ~32–37%, weak verification ~21–24%. Checkable rubrics + an isolated verifier gate sit on the highest-leverage categories. Post-hoc failure *attribution* is near-random (best: 14.2% at step level) — evidence bundles beat blame. [arXiv:2503.13657](https://arxiv.org/abs/2503.13657) · [arXiv:2505.00212](https://arxiv.org/abs/2505.00212)
- **Single agents reach multi-agent parity at equal compute** — token-matched single agents match or beat MAS; MAS only wins when single-agent context degrades. [arXiv:2604.02460](https://arxiv.org/abs/2604.02460) · [arXiv:2601.12307](https://arxiv.org/pdf/2601.12307)
- **Debate loses to independence** — multi-agent debate often fails to beat CoT/self-consistency; agents flip correct→incorrect to agree with peers; accuracy can *decline* over rounds. [arXiv:2502.08788](https://arxiv.org/abs/2502.08788) · [arXiv:2509.05396](https://arxiv.org/abs/2509.05396) · [arXiv:2310.01798](https://arxiv.org/pdf/2310.01798)
- **Vote visibility causes herding** — revealing authorship increases self-voting; showing ongoing votes amplifies premature convergence. Keep judges blind to authorship and to each other. [arXiv:2509.23537](https://arxiv.org/abs/2509.23537)
- **PoLL juries** — panel of 3 small cross-family judges beats a single large judge across 6 datasets at ~1/7 the cost, with less intra-model bias. [arXiv:2404.18796](https://arxiv.org/abs/2404.18796)
- **BoN-MAV: aspect verifiers are their own scaling axis** — multiple verifiers each checking one *facet* gain up to ~10% (large models) / ~20% (small), and keep improving where reward-model verification and self-consistency plateau. [arXiv:2502.20379](https://arxiv.org/pdf/2502.20379)
- **Weaver** — accuracy-weighted aggregation of weak verifiers beats majority voting by +13.5%; needs per-verifier accuracy history. [arXiv:2506.18203](https://arxiv.org/abs/2506.18203)
- **Self-MoA & non-monotonic voting** — ensemble the best model rather than mixing in weaker peers; voting gains first rise then fall with more calls. Heterogeneity pays only as *function specialization*. [arXiv:2502.00674](https://arxiv.org/abs/2502.00674) · [arXiv:2403.02419](https://arxiv.org/abs/2403.02419) · [X-MAS arXiv:2505.16997](https://arxiv.org/abs/2505.16997)
- **MASS: prompt optimization beats topology optimization** — agent-level prompt optimization carries ~2× the gain of topology search; beneficial topologies are "a small fraction" of the design space. Ultragoal's implementation surface is literally prompts. [arXiv:2502.02533](https://arxiv.org/abs/2502.02533)
- **Rubric-guided test-time verification** — taxonomy-derived rubrics + verifier feedback loops beat generic LLM-judging by 12–48% meta-eval F1. Closest academic twin to ultragoal's loop. [arXiv:2601.15808](https://arxiv.org/html/2601.15808v2)

## Implemented

> Status update, 2026-06-11 (later the same day): the owner redirected toward the vanilla single-grader architecture of the founding article. Panel verification was removed from the engine in v0.14.0 — the gate accepts one verdict grammar again — and the aspect-lens idea survives as optional dispatch guidance in the goal skill (extra verifier passes with distinct lenses; the gate still needs only the final PASS). The evidence below stands; the engine grammar does not.

1. **Panel verification (`verify: panel`)** — `scripts/goal-gate.sh` (third `verify` value; release requires the last verdict *per lens* to be `ULTRAGOAL-VERIFIED: PASS rubric=<current-hash> lens=<checks|refute|constraints>` for all three lenses; fail-open preserved), `tests/gate-test.sh` (6 new cases: panel protocol surfaced, full panel releases, partial panel blocks naming the missing lens, un-lensed PASS blocks, later lens FAIL beats its older PASS, stale-hash lenses block), `agents/verifier.md` (panel-lens protocol + verdict format + blindness rule), `skills/goal/goal-template.md` + `skills/goal/SKILL.md` (the `verify: panel` contract and parallel-dispatch protocol), `skills/setup/SKILL.md` + `installer/cli.mjs` (verification knob gains `panel`), `docs/research-foundations.md` (evidence rows).
2. **Fan-out sizing rules** — `skills/goal/SKILL.md` "Match the machinery to the goal" section: research-backed sizing guidance for scout/subagent fan-out.

Cost posture (owner direction): ultragoal is a premium, results-first product — machinery is chosen for the result, never trimmed for the token bill. The UX obligation that comes with that is *communication*: the goal recap states, in rough human terms, what a run will take — in units the loop actually counts (turns, subagent fan-outs), never wall-clock estimates, which agents are reliably bad at — and every point of choice states its cost factually — panel fires once per goal at the final sign-off, about two extra verifier passes. Cheaper-equal substitutions are still taken where research shows no result cost (the mechanical `checks` lens runs on a small model per PoLL); interim per-claim verification stays single-verifier because tripling it buys nothing for the result, not because it saves tokens.

Validation: `bash tests/gate-test.sh` (47 cases) exits 0; `claude plugin validate .` passes; `node --check installer/cli.mjs` clean.
