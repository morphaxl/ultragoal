## [2026-06-14] Gate's evidence parser and rubric hash are coupled to cosmetic formatting — a no-op reformat forced an expensive re-verify
- trigger: dogfooding the chat-challenges-p1 goal, the gate's checked-without-evidence count falsely flagged items whose description wrapped across multiple lines (the evidence line was real, just not on the immediately-following line), and the fix — collapsing each item to one line, plus reflowing one evidence block — moved the rubric hash three times (3000890955 → 3648216910 → 785393278). Each move invalidated a fresh verifier PASS and forced a re-run: a ~42.9k-token / 3-min panel re-verify for a change the Decision journal itself labeled "no check weakened."
- component: gate
- why: two coupled mechanisms. (1) the evidence ledger awk (`goal-gate.sh:157-160`) inspects only the single line immediately after each `- [x]` box, so a multi-line item *description* reads as "no evidence." (2) the rubric hash (`goal-gate.sh:97`) strips only the FIRST `- evidence:` line and normalizes checkboxes, but description prose, `- check:` bullets, and evidence *continuation* lines all feed `cksum` — so a purely cosmetic edit moves the hash. Flaw 1 forces a reformat; the reformat trips flaw 2. The script's own comment at L95 ("evidence lines are normalized out, so marking items done never voids a verdict") over-promises: only the first evidence line is normalized out, not its continuations.
- improvement: (a) evidence parser — scan forward from a `[x]` box to the next box/blank boundary and count it satisfied if ANY line in that block contains `evidence:`, removing the single-line constraint. (b) hash — strip the ENTIRE evidence block (from `- evidence:` to the next `- [`/blank), and ideally hash only normalized check *identity* (item number + `- check:` text, whitespace-collapsed) so prose reflow and `- check:`-bullet cleanup don't void a substance-only verdict; the hash should fire on weakening a check, not on rewrapping a line. Fix the L95 comment to match whatever it actually normalizes. (c) until then, the goal-template should model single-line descriptions with `- evidence:` immediately under each box, the goal skill should state it, and the gate's no-evidence error should hint "the evidence line must be the FIRST line under the box."
- provenance: [USER-FEEDBACK · 2026-06-14] ("is there anything to learn from this?") + [VERIFIED] by reading `goal-gate.sh:97,157-160`.
- resolved: fixed in commit `3195a71` (2026-06-14) — evidence parser is now block-aware (accepts `evidence:` anywhere in an item block) and the hash strips the whole evidence block; check/description text still feeds the hash so tamper-protection is preserved. Regression tests added (gate-test.sh: 77 pass). The (c) doc-mitigation became unnecessary — fixing the parser removed the single-line-description constraint entirely.

## [2026-06-14] UI goal placed a feature in the wrong nav spot — spec confirmed the work plan, not the on-screen end state
- trigger: a "Messages tab" was built as a home-header icon instead of a primary bottom-tab item. The screen, socket hook, and perf fixes were all built correctly — the miss was purely *placement*. The user pictured a bottom-bar destination; the agent, seeing the existing `messages` route set to `href: null` in the tab config, wired a header entry-point — a defensible read of an ambiguous spec. Caught only when the user saw the running app.
- component: interview + skill-prompt (recap) + rubric. Three gaps at once: (1) the interview never surfaced "where does Messages live?" as a fork — it was silently inferred from existing config; (2) the recap confirmed the *work plan* ("build a Messages tab") in prose, where "tab" carries two different pictures, instead of an inspectable *end state*; (3) the rubric checked "the list renders / stub gone" but never *how the user reaches it*, so the gate passed it.
- why: prose under-specifies spatial/IA decisions — a noun like "tab" reads as unambiguous to both parties while meaning different things, and nothing in a sentence exposes the divergence. The recap described the journey (work) rather than the destination (what exists), so the placement decision stayed implicit. And existing config (`href: null`) silently answered a question that was actually the thing being changed.
- improvement: (a) goal skill Phase 2 — add **placement / IA** as a high-leverage interview fork that must be *surfaced, never inferred from existing config*. (b) goal skill Phase 4 — for any goal that adds/changes a screen or navigation, the recap **leads with a "What you'll see" block** (nav map + screen inventory + ASCII wireframe + flow + stated assumptions), describing the built thing from the user's chair, and uses `AskUserQuestion` previews to show layout options side-by-side; the block travels into the finish summary and any cross-session handoff prompt so the locked picture isn't re-derived from config. (c) rubric-guide + the rn-feature / nextjs-react-feature templates — a **reachability/placement** check (wired ≠ renders ≠ reachable): a new destination needs an item asserting it appears in every nav variant, not just that the route renders.
- provenance: [USER-FEEDBACK · 2026-06-14] (the misplaced Messages tab, caught on the running app; "ensure both human intent and agent understanding is the same").
- resolved: implemented 2026-06-14 in skills/goal/SKILL.md (Phase 2 fork + Phase 4 "What you'll see" block), skills/goal/rubric-guide.md (reachability anti-pattern + wired/renders/reachable split), and the rn-feature / nextjs-react-feature templates (placement check + "What you'll see" pointer). Suite green (77 pass).

## [2026-06-14] Rubrics verified structure (wired, mocked-green), never live behavior — a new auth integration 401'd in real use and cascaded to a global logout
- trigger: chat+challenges P1 shipped as SOLID on "46 mocked tests + typecheck green"; the novel Arcade→DG auth bridge — the single most fragile new seam — was the exact thing mocked, so no check ever minted a real token and asked the real staging gateway "do you accept this?" It 401'd the first time a real user hit it, and a pre-existing http-client footgun (sign out on any 401) turned the 401 into a global logout. P1 had even self-flagged "DATA_SESSION_TOKEN_SECRET not in Arcade env yet" — and still passed as done.
- component: rubric + verifier (and the gate that trusted them). Four sub-failures: (1) mocked tests accepted as verification of a live external boundary — we mocked the seam we were least sure of; (2) a self-disclosed "won't run until X" became a footnote instead of a blocking item, so the goal closed SOLID over a known runtime gap; (3) all live exercise deferred to a final manual device round — the first real call was the user, by hand; (4) per-feature rubrics test happy path + own edges, never how the feature's *failure* interacts with the rest of the app, so the global-logout cascade sat untouched.
- why: the loop's deepest bias is "wired ≠ working." Every static/mocked check proves the code is present and the orchestration is right; none proves the real dependency accepts the call. Structure reads as success while the behavior the user wanted never ran. The verifier inherited the blind spot — it re-ran the mocked checks and saw green.
- improvement: extend the evidence ladder to **wired → renders → reachable → live**; make the rubric's governing principle "the user's acceptance test in observable behaviors, verified at the layer the behavior lives in." Concretely: (a) a cross-boundary claim needs a **live smoke** (one real call that succeeds against the real/staging dependency) — mock what you're sure of, live-test the least-certain seam, early; (b) a **self-disclosed runtime gap is a blocking `[ ]` item**, never a footnote — the verifier fails any item it touches and won't sign SOLID over it; (c) a **failure-cascade** check on new endpoints (on 4xx/5xx: clear error, graceful degrade, no global logout); (d) sequence a thin end-to-end live slice early rather than deferring all real exercise to a final manual round.
- provenance: [USER-FEEDBACK · 2026-06-14] (the P1 401 + logout cascade; "focus more on behaviour", "make rubrics smarter and aligned with what the user actually wants", "modify the philosophy and the UX so this doesn't happen").
- resolved: implemented 2026-06-14 in rubric-guide.md (lead principle "rubric = user acceptance behaviors"; principle-1 boundary/live + mock rule; evidence-ladder section now wired/renders/reachable/live; three anti-patterns — mocked-only boundary, disclosed-gap-as-footnote, no-failure-cascade), SKILL.md (Phase 2 DoD-as-behaviors + boundary elicitation; Phase 3 defect taxonomy + thin-slice-early; while-loop disclosed-gap-is-blocking rule), agents/verifier.md (mocked-only boundary + disclosed-gap = not a PASS), and the rn-feature / nextjs-react-feature templates (live-smoke + failure-cascade items). Suite green (77 pass).
