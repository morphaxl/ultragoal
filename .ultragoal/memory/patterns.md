## Current understanding

- Write rubric check-phrases as literal grep strings and put that exact string in the artifact — a paraphrased heading ("setup answers" vs "knobs") makes a check unfalsifiable by grep and forces the verifier to judge substance. [VERIFIED S3, S4 · verifier flagged it twice in two goals · 2026-06-10]

- A fresh-context verifier compares the WORKING TREE to HEAD and will flag uncommitted prior-session work as scope-creep against a "nothing-else-changed" constraint — correctly, because it has no way to know that work was already approved. Two lessons: (1) when a goal runs on a working tree that already carries approved-but-uncommitted changes, scope the "unchanged" constraint to "unchanged BY THIS GOAL" from the start, or commit the prior work first so HEAD is the real baseline. (2) When the verifier FAILs on a baseline-ambiguity like this, DON'T rewrite the constraint to clear it — that's goalpost-moving; surface it to the user as the scope decision it is, get the baseline ratified, THEN amend + re-verify on a fresh hash. The amend voids the old verdict automatically (hash binding), forcing an honest re-check. [VERIFIED S9 · verifier FAIL→user-ratify→amend→PASS cycle on rigor-modes · 2026-06-13]

- For "X never affects Y" guarantees, the decisive check is "X never appears in a control-flow construct in Y's code", not "X is absent from Y". rigor legitimately appears in the gate's comments + a printed message; the honest check is `grep -n rigor gate.sh | grep -vcE ':[[:space:]]*#|echo'` == 0 (zero non-comment/non-echo mentions), which proves the separation without forbidding documentation. [VERIFIED S9 · item-7 reformulation that passed · 2026-06-13]

- For RESEARCH goals on an unfamiliar codebase, the independent verifier must RE-FETCH SOURCE and grep it, not just re-run the memo's greps — grep checks only prove the memo *says* X, never that X is true. Give the verifier the raw-fetch recipe in its dispatch (`gh api`/`curl raw.githubusercontent.com`; it has Bash but not WebFetch). On the omp memo this caught two confident factual errors a grep-only pass would have rubber-stamped. Rubric design follows: a research rubric needs at least one item whose check is "the verifier independently re-fetched the cited source and the claim held," not just "the memo contains a citation." [VERIFIED S10 · 2 source-grounded FAILs then PASS on omp memo · 2026-06-13]

- Test installs from a sandbox + the real cache path, not just --plugin-dir: the hooks.json duplicate-load failure only manifested on cached installs. Cheap: temp git repo + `cli.mjs --yes`. [VERIFIED S2 · ran it this goal · 2026-06-10]
- A fresh-context verifier pays for itself: it caught a stale "4 questions" string the worker (me) missed after three reviews of the same file. [VERIFIED S2 · verifier report · 2026-06-10]

- Parallel community-scoped research agents with a strict output contract (IDEA/SOURCE/PROPERTY/MAPS-TO/AXIS/SIGNAL, max 10 findings, "no preamble — your final text is raw data") returned 40 usable findings across 4 sweeps in ~5 min. Cross-community CONVERGENCE is the ranking signal: the ideas independently surfaced by 3+ communities (evidence bundles for judges, rubric defect taxonomy, compact check output) were the ones worth implementing. [VERIFIED S6 · harness-research goal · 2026-06-11]

- Keeping research-scout prompts in orchestration/reliability vocabulary (an explicit "stay in software-engineering register" line in each prompt) avoids classifier-driven model switches on Fable 5: 4 scouts in the orchestration sweep ran clean, where the robustness goal's security-register scout triggered a mid-run switch. [VERIFIED S7 · multiagent-orchestration goal, 4/4 scouts completed on-model · 2026-06-11]

- The final-sign-off dance — box flips / evidence edits voiding fresh verdicts — is engineered away: the rubric hash normalizes out checkbox state AND the whole evidence block, binding verdicts to check text only. One verifier pass at the end suffices; editing a check still voids. v1.1.0 did this for single-line evidence; it was INCOMPLETE — the hash stripped only the first `- evidence:` line and the evidence parser only looked one line below a box, so multi-line descriptions/evidence still tripped it (cost a needless panel re-verify). Fully closed in 3195a71 (block-aware parser + whole-block strip). [VERIFIED S7 6 gate tests · S16 multi-line gap found+fixed, 77 tests · 2026-06-12/14]

- For UI/IA work, spec & confirm the END STATE the user will see, not the work plan — lead the recap with a "What you'll see" block: nav map (post-change bar/header), screen inventory (name·purpose·how reached), ASCII wireframe, tap-flow, stated assumptions; use AskUserQuestion previews to let them PICK a layout. Prose like "a Messages tab" carries two pictures (bottom-bar destination vs header icon) and the divergence only surfaces in a drawing — which also forces the agent to read the current IA (where placement landmines like `href:null` hide). Pair with a rubric reachability check (wired ≠ renders ≠ reachable). The block must travel into the finish summary AND any cross-session handoff prompt, or the picture gets re-derived from config in the next session — which is exactly how the misplaced-Messages-tab bug reached code. [VERIFIED S16 · implemented in goal SKILL Phase 2/4 + rubric-guide + rn/nextjs templates · USER-CORRECTION 2026-06-14]

- Transcript decomposition beats live A/B for cost analysis: finished agent runs leave full per-message usage in ~/.claude/projects/<cwd-slug>/*.jsonl (+ subagents/) — summing usage fields located the harness's cost structure (messages × context, ceremony prose, verifier share) in one free pass, where each live bench measurement costs ~1.2M tokens/run. Decompose first; measure only what judgment can't settle. [VERIFIED S7 · smoke-run decomposition drove the cost findings · 2026-06-11]
